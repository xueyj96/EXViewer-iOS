# App 通用设计准则

共用版 v2.0。做一页时先写清入口、主任务和返回位置，再定布局基准、状态归属和验收场景。共用正文给出设计方法和 iPhone 起步值，具体控件尺寸与平台实现见各项目附录。

## 外观与交互准则

### 页面和内容层级

- **一页先服务一件事。** 列表帮助找到内容，详情帮助判断，播放器和阅读器让人专心看。每个操作区突出当前最常用的动作，低频动作收进菜单。主要页面用底栏切换，页内同级视图用分段控件。
- **按阅读顺序放内容。** 标题、能识别对象的信息和主动作靠前。作者、集数、页数和状态按当前任务取舍，长简介与完整标签到详情再展开。数据使用真实来源，缺项用中性占位。
- **主题和材质按用途复用。** 普通页面从启动和转场首帧就使用当前主题底色。媒体浮层同类控件共用一套材质，在明暗和复杂画面上检查可读性。文字密集的面板可以用更实的底。 [Apple HIG 布局](https://developer.apple.com/design/human-interface-guidelines/layout) · [材质](https://developer.apple.com/design/human-interface-guidelines/materials)

### 布局、对齐和留白

1. **给每一类元素定基准。** 全屏媒体以整屏中心为准，内嵌媒体以容器中心为准。返回、关闭和进度条在安全区内定位。普通页的标题、筛选、列表和卡片共享内容起始边。同行文字按基线对齐，图标在自己的位置上按视觉重心对齐。
2. **先定外框，再定里面怎么排。** 页面容器统一算安全区和内容边距。顶部、底部和侧边操作区各有明确占位，中间内容填充剩余空间并按需滚动。临时面板覆盖媒体时沿用原画面中心。要让顶栏中段严格居中，可给两侧留等宽动作位。窄屏或大字号优先保住主动作和点击区，次要信息换行、换列或收进菜单。
3. **分别量外框、图标和点击区。** 控件外框的可见边缘用来比齐，图标在框内做光学居中，点击区单独验证。iPhone 常用动作以 44 × 44 pt 的点击区为目标。各项目把页边距、组件间距、内外圆角和可见尺寸集中维护。紧凑例外记在附录，分别验普通字号和大字号下的点按。 [Apple HIG 按钮](https://developer.apple.com/design/human-interface-guidelines/buttons) · [辅助功能](https://developer.apple.com/design/human-interface-guidelines/accessibility)

| iPhone 留白起步值 | 优先用在哪里 |
| --- | --- |
| 4 pt | 图标和同行短文字、标签和相邻内容的紧密间隔 |
| 8 pt | 同组项目之间、紧凑卡片的列间距 |
| 12 pt | 内容卡片内边距、需要多一点空间的同组控件 |
| 16 pt | 安全区以内的常规左右页边距，顶栏和列表共享这条内容边 |
| 24 pt | 两个独立内容区之间 |
| 32 pt | 页面级分段，例如概要与正文之间 |

以横向安全区无额外内缩的 390 pt 竖屏为例，两侧各留 16 pt，内容宽 358 pt。顶栏两侧各给 44 pt 动作位，与中间各隔 8 pt，中间还有 254 pt。双列卡片共用同一条内容边，列间 8 pt 时每列 175 pt。把这些当成可检查的布局条件。项目已有的内框缝隙、栏高和圆角采用附录的数值。

### 卡片、标签和文字

- **按任务选列表或卡片。** 快速比较、排序或批量管理适合结构稳定的列表行。作品需要靠封面识别、展示简短状态或单独操作时，用卡片。卡片内按「封面、标题、次要信息、状态或动作」组织，同类卡片共享内容结构。
- **预览位由容器先定。** 封面未到、失败或比例异常时沿用卡片列宽和预览位置。按需要裁切预览，阅读或全屏播放默认按原比例完整展示。长标题按页面密度设行数，完整名称在详情和辅助技术中可读。重点状态和主要按钮有预留位置，加载、关注或多选时保住相邻内容的位置。
- **把类型、状态和筛选分清。** 「短剧」说明类型，「已离线」说明状态，「仅看已下载」改变筛选。状态标签用短词贴着对象，可点击筛选项要有可见的选中和取消方式。卡面优先展示对当前任务有用的少数标签，完整内容在详情里读。

### 按钮、图标和文案

- **按用途选控件。** 按钮执行动作，开关控制持续生效的两态设置，分段控件在少数同级选项间切换。同一个操作区用实色或强调色突出主动作，次要操作用描边、文字或菜单。确认高影响操作时说清对象、范围和后果，可逆操作可给「撤销」。
- **用图标让动作容易认。** 播放、暂停、明确位置的关闭可以只用图标。书架、历史等常用入口可以用图标加文字。「移到分组」「删除离线文件」用文字写清动作。同一动作跨页用同一符号，VoiceOver 标签读出动作和对象。用勾选、形状或文字与颜色一起表达选中。iOS 桌面图标保留缩小后能认出的主形状，由系统处理圆角。 [Apple HIG 图标](https://developer.apple.com/design/human-interface-guidelines/icons) · [App 图标](https://developer.apple.com/design/human-interface-guidelines/app-icons)
- **按钮说下一步，状态说现在。** 栏目写「历史」，操作写「继续阅读」。当前为正序时，切换动作写「倒序排列」，双选项则用「正序／倒序」及选中态表达当前顺序。站点收藏、稍后再读、浏览缓存、离线下载使用各自的词。 [Apple HIG 界面写作](https://developer.apple.com/design/human-interface-guidelines/writing)

| 场景 | 显示文字 | 下一步 |
| --- | --- | --- |
| 筛选请求成功但结果为空 | 没有符合条件的作品 | 调整筛选 |
| 单页失败 | 这一页加载失败 | 重试或继续翻页 |
| 收藏提交中 | 保存中… | 继续浏览 |
| 收藏提交失败 | 收藏未保存 | 重试 |
| 作品正在缓存 | 已缓存 2/6 集 | 在该作品上查看进度 |
| 有观看记录 | 上次看到第 5 集 · 12:34 | 继续观看 |

### 交互、反馈和返回

- **给每个动作划清范围。** 整卡点按进入详情，卡内收藏或更多有独立的触发范围。主要操作可见，手势作为快捷方式。定义系统返回、翻页、切集和拖进度的优先级。在线和离线入口共用播放操作，各自按可用内容限定队列与边界。侧栏可配置时保留可用默认项和固定退出入口。
- **先有反馈，再等结果。** 按下、选中、提交中和不可用可区分。状态改变后保住控件位置和主要操作。后台预载默认静默，当前内容卡住就在内容区反馈，失败就地重试。整页提示留给当前任务确实被阻断的情况。
- **退出后接得上。** 从详情、作者页或全屏返回时恢复筛选、排序和浏览位置。管理态用原底栏的位置显示批量操作，列表沿用原列宽和滚动锚点。续看按当前账号、内容 ID、实际页码或播放时间恢复。

## 代码设计准则

### 职责和复用

| 职责 | 由哪一层负责 |
| --- | --- |
| 布局、导航、可见性、手势 | 页面和共用组件负责布局、展示和发出动作。按压和面板展开等临时状态放在需要它的界面。 |
| 列表、筛选、游标、续看、操作状态 | 对应功能的 model 或 store 持有状态与规则。界面从这一份状态推导反馈。 |
| 网络、账号、文件、媒体渲染 | 现有服务和平台适配层提供明确的读写能力。请求层交付数据或错误，播放器提供缓冲、首帧、暂停和定位等结果。 |

同一种操作共用行为，入口明确传入来源、筛选、可用队列和操作权限。参数和返回值反映实际能力。先复用项目已有组件和接口，再把语义相同的重复逻辑收进负责它的模块。原生项目用各自的状态模型，跨端项目用已有界面、桥接和本地服务边界。 [Apple SwiftUI 界面状态](https://developer.apple.com/documentation/swiftui/managing-user-interface-state)

### 状态、异步和失败

- **状态和身份写进模型。** 区分没有数据、已有内容且正在刷新、空结果、失败和取消。收藏等写操作区分用户想要的状态、提交中和已确认的状态。列表和任务按站点、账号、入口、筛选、内容 ID 及需要的版本区分。
- **提交前核对任务是否仍适用。** 用请求标识或代次把结果绑定到发起时的账号、对象和上下文。快速切换、取消和清理后拒绝过期写入。多个入口等待同一份内容时复用在途请求，个别入口退出后保留仍有人使用的任务。 [Swift 并发与取消](https://docs.swift.org/swift-book/LanguageGuide/Concurrency.html#Task-Cancellation)
- **写操作可重试、可核对。** 收藏、保存和删除表达明确的目标状态与对象，对重复点击去重。响应不明时先读回同一对象的状态，再决定是否重试。局部失败保留已完成内容，授权、额度、限流和磁盘问题按对应条件暂停或恢复。

### 缓存、预载与离线

| 本地内容 | 代码约定 |
| --- | --- |
| 列表快照 | 按站点、账号、入口、筛选和排序匹配。允许复用时先恢复再校验，提交新结果与对应游标时去重并保住浏览位置。 |
| 浏览媒体缓存 | 按作品、页码或集数、画质与版本匹配，在允许的权限范围复用，按容量回收。 |
| 离线副本 | 单独管理文件、完成状态和占用空间，设置明确的暂停、继续和移除入口。 |
| 历史、进度、书签、设置 | 按数据来源与账号范围持久化，清理浏览缓存时保护这些记录和离线副本。 |

- **调度先服务当前画面。** 分开限制预载范围、实际并发、单文件和总容量，留出磁盘余量。复用有效缓存和在途任务。后台预载遇到单项失败时局部处理，整体受限时给出准确的暂停原因。HTTP 缓存遵循服务端缓存指令和响应变化条件。 [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html#section-4)
- **先验证文件，再发布离线状态。** 先暂存并检查完整性、可读性及所需媒体文件，再提交索引。区分排队、下载、部分完成和可离线。中断或重启后核对文件和索引，按实际解码、起播、拖动或断网翻页验收。
- **清理和升级有明确范围。** 清理按浏览缓存、离线副本和用户记录分开执行，保护在读文件，拦住旧任务的迟到写入。自动保存尊重手动移除选择。iOS 可回收数据使用系统缓存目录，离线副本和用户记录按用途选持久目录与备份策略。变更目录或索引时，用旧版样本验证迁移、重启、读回和实际打开，并准备失败恢复方式。 [Apple 本地数据与备份](https://developer.apple.com/documentation/foundation/optimizing-your-app-s-data-for-icloud-backup)

## 改动与验收

- **先定哪一层改。** 「太大」拆成图标、外框、点击区和周围留白。反复出现的边线、间距和材质问题回到共用布局或组件。某页有特殊任务或空间约束时，在项目附录说明使用条件。
- **外观用同条件对照。** 固定作品、设备尺寸、字号、主题和方向，分别量可见边、文字基线与点击区。切换加载、选中、管理态、横屏及浅深色，看内容列和操作位置能否稳定。弹层、转场和播放首帧用录屏检查。共用规则变更后再验一个使用它的入口。
- **功能沿真实路径验。** 从实际入口做完主要操作，再返回或续看。按改动范围覆盖慢网、快速切换、局部失败、取消和重复操作。涉及缓存时对照冷启动、暖缓存、断网、坏文件和清理中的任务。用同一批内容和网络条件比较请求、流量、首屏、首帧或翻页时间。
- **交付证据分开记。** 记录场景、目标构建、环境和结果。构建、安装读回、文件或索引读回，以及真机实际操作分别记。旋转、手势、离线起播等体验以实际走过的路径为准。

## ExHViewer 验收示例

- **发现和组合搜索。** 从发现页进入搜索，组合作者和包含／任一／排除标签。区分已执行的条件和正在编辑的草稿。打开一部作品再返回，结果位置与生效条件可接续。
- **阅读和续读。** 用一部有极宽封面、长页和坏页的作品连续翻页。封面加载后网格列边和当前浏览位置保持稳定，阅读页以整屏中心展示原比例的画面。坏页可就地重试或跳过，退出再进入时回到实际读到的页码。账号或额度受限时给出相应状态。
- **资料库和多选。** 分清本机稍后再读、站点收藏、阅读历史与离线下载。在相同屏宽和字号下切换入口，核对顶部两行的起始边和首条内容的位置。用大字号检查多选后的移动、移除与退出入口。从操作文案分辨是将作品移到其他收藏分组、移除站点收藏还是删除本机离线文件。退出后恢复常规底部导航。清理浏览缓存后复验手动保存的离线副本。
- **切入与退出管理态。** 从列表中间进入管理态，核对操作切换到原底栏的位置，列表项的宽度和正在看的位置保持。勾选后退出，检查常规导航和原列表位置。
- **翻页预载与离线副本。** 从详情进入阅读器，连续翻到正在预载的页，核对在途请求能否复用，以及单页失败时后续页能否继续。保存到本机时检查同账号、同画质的有效缓存是否复用。额度不足时已有图可复制，缺图应显示暂停原因。清理浏览缓存后断网打开保存的副本。
